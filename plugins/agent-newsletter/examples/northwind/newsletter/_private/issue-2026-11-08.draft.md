# Northwind Analytics agent log: week of 2026-11-02

*Issue 7. How a 12-person company runs on a team of AI agents, written from the agents' own handoffs, decisions and failure notes.*

A week of migrations and the three small failures that came with them. Every one of them produced a rule, and every rule is now in a file an agent reads before it starts work.

## What shipped

- **Scheduled CSV exports** (engineering): dashboards now export nightly to the customer's own bucket, so analysts stop screenshotting charts.
- **Queue migration** (engineering): ingestion workers moved to the new queue; the hosting bill went from $3,400/mo to $2,150/mo.
- **Faster dashboards** (engineering): cold load down from about 4.1s to 1.6s by caching one schema lookup.
- **A shorter onboarding sequence** (growth): five emails down to three, each asking for exactly one action. Trial-to-paid on the Team plan is 18%, up from 14%.
- **A claim protocol for tasks** (ops): agents now write `claimed-by: <role>` in an inbox before starting.

## What broke

- **The export ran twice** (Nov 4): after the migration, the old cron trigger and the new queue consumer both started the nightly export. 37 accounts got duplicate files and one customer's pipeline double-counted a day. We issued about $800 in credits. A customer told us before any alert did.
- **The right email to the wrong people** (Nov 5): the growth agent sent "finish connecting your data source" to people who already had, because it used Monday's segment snapshot instead of the live list.
- **Two agents, one task** (Nov 6): the status page task sat in two inboxes "to be safe". Engineering and ops both posted an update within ten minutes, with slightly different explanations.

## The rule each failure produced

| Failure | Rule now in force | Where it lives |
|---|---|---|
| The export ran twice | Every scheduled job carries an idempotency key; a duplicate run is a no-op plus an alert. | DECISIONS.md D-029, LESSONS.md |
| Wrong people emailed | Re-read the live audience right before any send; snapshots are for planning only. | LESSONS.md, handoff/growth.md |
| Two agents, one task | One task, one inbox, one `claimed-by` line. First claim wins. | DECISIONS.md D-030, LESSONS.md |

## One lesson

All three failures were the same failure: a step that two things were allowed to do, or that nothing was told to re-check. The migration checklist said "switch off the old trigger" with no owner. The send step never said "refresh". The task was copied "to be safe". Agents are very good at doing what a file says and very bad at noticing what a file leaves out. So the fix is never "be more careful"; it is a line in a file that makes the second run, the stale read, or the second claim impossible or loud.
